# ภารกิจที่ 3 · Idea Validation

เอาไอเดียไปถามกลุ่มเป้าหมายจริงอย่างน้อย 3 คน แล้วส่งสรุปไม่เกิน 1 หน้า
ภายใน **16 กันยายน 2569 เวลา 23.59 น.**

## ไฟล์ในโฟลเดอร์นี้

| ไฟล์ | คืออะไร | สร้างด้วย |
|---|---|---|
| `CareSignal-ValidationKit.pdf` | ชุดสัมภาษณ์ 10 หน้า พิมพ์ไปใช้จริง | `node tools/make-validation-kit.mjs` |
| `results.json` | ข้อมูลดิบรายคน กรอกเองหลังสัมภาษณ์ | แก้ด้วยมือ |
| `CareSignal-ValidationSummary.pdf` | ใบสรุป 1 หน้า สำหรับส่งในแบบฟอร์ม | `node tools/make-validation-summary.mjs` |

ไฟล์ PDF ถูก gitignore ไว้ ต้องสั่งสร้างเองในเครื่อง

## ลำดับการทำงาน

1. **พิมพ์ชุดสัมภาษณ์** — หน้า 3 (ใบยินยอม) พิมพ์เท่าจำนวนคน · หน้า 4–5 สำหรับผู้สูงอายุ ·
   หน้า 6 สำหรับครอบครัว · หน้า 7 สำหรับเจ้าหน้าที่ · หน้า 8 (บัตรฟีเจอร์) พิมพ์ใบเดียวแล้วตัด ·
   หน้า 10 พิมพ์เท่าจำนวนคน
2. **อัดวิดีโอแนะนำระบบ 60–90 วินาที** ไว้ในมือถือ เปิดให้ดูตอนสัมภาษณ์ตอนที่ 2
   (ไม่ต้องสวย ให้เห็นว่าเปิดแอป ตรวจ แล้วเห็นผล)
3. **สัมภาษณ์ 6–8 คน** — อ่านหน้า 2 ก่อนออกไปครั้งแรก คนละไม่เกิน 30 นาที
   ถ่ายรูปทุกครั้งหลังได้รับอนุญาตในใบยินยอมแล้ว
4. **กรอก `results.json`** ทีละคน แล้วตั้ง `"filled": true`
5. **สร้างใบสรุป** `node tools/make-validation-summary.mjs` — ตัวเลขทุกตัวคำนวณจากไฟล์ให้เอง
6. **ส่งแบบฟอร์ม** — ช่องแรกแนบ `CareSignal-ValidationSummary.pdf` ·
   ช่องที่สองแนบรูปถ่ายการสัมภาษณ์และภาพแบบสัมภาษณ์ที่กรอกแล้ว ไม่เกิน 5 ไฟล์

## กติกาที่ห้ามผิด

- ข้อมูลทุกตัวมาจากคนจริงที่ตอบจริง **ห้ามกรอกแทน ห้ามเดา ห้ามเติมให้ครบ**
- ถามได้ 3 คนก็เขียน 3 คน กรรมการให้คะแนนวิธีคิดและความซื่อสัตย์ของข้อมูล ไม่ได้ให้คะแนนจำนวน
- ห้ามใส่ชื่อจริง เบอร์โทร หรือที่อยู่ใน `results.json` ใช้รหัส `R01` `R02`
- ห้ามพิมพ์ตัวเลขทับในไฟล์ PDF ถ้าตัวเลขผิดให้แก้ที่ `results.json` แล้วสร้างใหม่
- ถ้ายังไม่ตั้ง `filled` เป็น `true` ใบสรุปจะขึ้นแถบแดงว่าห้ามส่ง

## การกรอก results.json

หนึ่งคนหนึ่งบล็อกใน `people` · ค่าที่ยังไม่ได้ถามให้ปล่อยเป็น `null` **อย่าเดา**
เพราะตัวหารของทุกสัดส่วนคือจำนวนคนที่ถูกถามข้อนั้นจริง

| ช่อง | ความหมาย | ค่าที่ใส่ได้ |
|---|---|---|
| `code` | รหัสผู้ให้ข้อมูล | `"R01"` |
| `group` | กลุ่ม | `"elder"` `"family"` `"staff"` |
| `method` | วิธีเก็บ | `"interview"` `"survey"` `"phone"` |
| `fell12m` | เคยล้มใน 12 เดือน | `true` `false` `null` |
| `nearFall` | เคยเกือบล้ม | `true` `false` `null` |
| `neverAssessed` | ไม่เคยมีใครวัดการทรงตัวให้ | `true` `false` `null` |
| `setsUpAppsSelf` | ลงแอปเองได้ | `true` `false` `null` |
| `understood` | อธิบายได้เองว่าโปรแกรมทำอะไร | `true` `false` `null` |
| `wouldTryWithHelp` | จะลองใช้ถ้ามีคนช่วยตั้ง | `true` `false` `null` |
| `gaveContact` | ให้ช่องทางติดต่อกลับไว้ | `true` `false` `null` |
| `top3` | บัตรฟีเจอร์ อันดับ 1 2 3 | `["F4","F1","F3"]` |
| `concern` | ข้อกังวลหลัก ประโยคเดียว | ข้อความ |
| `quote` | คำพูดจริง | ข้อความ |

`actions` คือสิ่งที่ทีมจะเปลี่ยนเพราะ Feedback — คู่ `finding` (ได้ยินอะไร) กับ `change` (จะเปลี่ยนอะไร)
เขียนให้เจาะจงพอที่คนอ่านจะบอกได้ว่าเปลี่ยนตรงไหนในระบบ
